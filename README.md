# Kawaii Physics Baker 使用说明

Kawaii Physics Baker 用于在 Unreal Editor 中预览并烘焙 KawaiiPhysics 骨骼物理。它以固定时间步长运行动画图，将身体、衣物等多个 Skeletal Mesh 的最终姿态分别保存为同步的 `AnimSequence`。

插件还提供两项配套功能：

- **物理校准**：用多个动作搜索 Kawaii 节点的 Physics Settings 与 Bone Constraints，逐候选进行原生 CPU 模拟和验收，保存结果并写回获选参数；也保留旧 GPU 倍率筛选模式。
- **烘焙衣物 IK 修正**：在游戏运行时，根据身体最终 IK 姿态修正已烘焙的衣物骨链。

## 准备工作

1. 确保项目启用 `KawaiiPhysics` 和 `KawaiiPhysicsBaker`，编译项目的 Editor 目标并重启编辑器。
2. 使用本仓库配套的 `Plugins/KawaiiPhysics`。Baker 依赖其中的共享碰撞、衣物碰撞和校准接口，不能假定任意原版 KawaiiPhysics 都能直接替换。
3. 准备角色 Skeletal Mesh 和非叠加（Non-Additive）的 `AnimSequence`。直接播放动画时，动画与对应 Mesh 必须使用同一个 Skeleton；工具不自动重定向。

烘焙蓝图及校准工具属于编辑器功能。游戏中播放生成的动画，或使用 `KawaiiPhysicsBakerRuntime` 提供的 IK 修正节点；不要把烘焙蓝图作为角色的运行时 Anim Class。

## 快速开始：烘焙一个 Mesh

### 1. 创建烘焙蓝图

在关卡编辑器选择 **Tools → 创建 Kawaii 物理烘焙蓝图**，选取目标 Skeletal Mesh，再保存蓝图，例如 `ABP_KawaiiBake_Body`。

工厂会设置对应的 Skeleton、预览 Mesh 和 `KawaiiPhysicsBakeAnimInstance` 父类，创建 `Bake Source Pose → Output Pose`，并打开 **Kawaii 物理烘焙** 面板。以后可通过该蓝图工具栏的 **物理烘焙** 按钮重新打开。

### 2. 配置 AnimGraph

在默认连接中插入 KawaiiPhysics 及空间转换节点：

```text
Bake Source Pose
    → Local To Component
    → KawaiiPhysics
    → Component To Local
    → Output Pose
```

在 KawaiiPhysics 节点上设置需要模拟的根骨骼、物理参数和碰撞约束。多个物理节点可以按需要串联。新建蓝图默认没有物理节点，仅保留默认连接会输出源姿态。

启用 `Bone Subdivision Collision Only` 时，细分点用于碰撞采样，真实骨段保持输入姿态的长度，并以真实父骨骼作为弹性回拉的锚点。旧版本若已把细分折叠产生的短骨段写入动画，更新代码不会自动修复这些轨道，需要从未烘焙源数据重新生成。

每个烘焙图必须有且仅有一个连接到输出求值路径的 `Bake Source Pose`。不要使用 Sequence Player、Blend Space Player 等动画播放器代替它；源动画和采样时间由烘焙面板统一控制。

### 3. 选择动画并预览

在 **物理烘焙** 面板设置：

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| Main Mesh | 创建时选择的 Mesh | 主部件，内部名称为 `Main` |
| Source Animation | 未设置 | 主部件的非叠加动画，与 Main Mesh 使用同一 Skeleton |
| 已烘焙人物动画 | 未设置 | 追加衣物时，选择 Main 使用的已有动画序列。预览和衣物导出都按这条序列的时间轴采样 |
| Sample Rate | `60` | 固定采样帧率，范围 `1–240` |
| Warm Up Frames | `60` | 正式采样前保持源动画第 0 秒姿态的物理预热步数，范围 `0–3600`；预热不写入动画 |
| Output Directory | `/Game/KawaiiBakes` | Unreal 内容目录，不是磁盘路径 |
| Output Prefix | `Baked` | 输出资产名前缀，必须是非空的合法资产名 |
| 烘焙后替换源动画（保持名称和引用） | 关闭 | 成功导出后，将 Main 结果写回源动画；覆盖前自动保存源备份 |

追加一套衣物时，选择 **已烘焙人物动画**，在 **附加部件** 中配置本次要导出的衣物，再点击 **仅烘焙附加部件**。Main 直接播放所选序列，衣物可以逐帧复制 Main 姿态或使用身体代理碰撞。导出的衣物代理关联所选人物序列。清空此选项即可恢复常规人物烘焙。

左侧 **物理预览** 直接显示身体和全部衣物部件的最终物理姿态，无需导出动画。配置完整时打开面板会自动预览；修改源动画、采样或部件设置后会重新预览。也可以点击 **编译并预览** 编译主图和所有部件图，从预热开始播放，或双击右侧动画列表切换动作。

视口下方提供动画时间轴、当前时间、帧号和缓存帧数：

- **拖动时间轴**：暂停并显示指定帧。拖动期间视口会持续刷新，已缓存的帧立即显示；尚未计算的帧按固定步长继续模拟，状态栏显示准备进度。继续拖动可以改变目标位置。
- **播放／暂停**：继续播放或暂停，保留当前物理姿态；在末帧点击 Play 会从头播放。
- **`|<` / `<` / `>` / `>|`**：跳到首帧、上一帧、下一帧、末帧。跳到尚未缓存的末帧会先补算整个动作。
- **循环**：默认开启，播放完毕后循环回放本次缓存；关闭后停在末帧。
- **聚焦角色**：重新把角色放入视野，可配合旋转、缩放视口检查穿模。
- **显示衣物代理**：叠加显示 Main 和各衣物部件已指定的代理球体／胶囊；播放、暂停和拖动时间轴时都跟随当前显示帧。此开关仅控制线框，不改变碰撞计算或烘焙结果；未指定代理定义的部件不显示线框。
- **显示骨骼**：叠加显示主角色 Main 当前预览帧的实际骨骼姿态，包含预览代理修正结果。修正配置中的骨链为黄色，其余骨骼为青色；连线和关节点可透过网格查看，支持播放、暂停和逐帧检查。此开关仅控制显示。

时间轴缓存仅保存在内存中，不创建动画资产。修改或重新编译参与的图、修改源动画会使旧缓存失效；修改图后点击 **编译并预览** 重新生成预览。烘焙时视口同样显示当前采样姿态，时间轴禁止拖动，导出始终从全新的预热状态开始。

### 4. 导出动画

点击 **烘焙新动画**，等待状态显示已保存同步结果，然后点击 **定位结果** 在内容浏览器中选中结果。

输出会自动保存，例如：

```text
/Game/KawaiiBakes/Baked_Walk_Main_a1b2c3d4
```

命名格式为 `<前缀>_<主源动画名>_<部件名>_<本次组 ID 前 8 位>`。默认每次生成新资产，不覆盖源动画或已有结果。记得保存烘焙蓝图，以保留图和面板设置。

在 **输出** 中开启 **烘焙后替换源动画（保持名称和引用）**，按钮会变为 **烘焙并替换源动画**。Main 结果仅在内存中构建和校验，不再额外生成独立的 Main 动画资产。附加部件动画和代理结果保存成功后，工具先在输出目录保存 `<Main 输出名>_SourceBackup` 完整备份，再把 Main 的骨骼动画和浮点曲线写回所选 **源动画**。原资产名称、路径和对象引用保持不变，已有 AnimBP、Blend Space、Montage 无需重新指定动画。源动画原有的 Notify、同步标记、Root Motion 和平台采样率设置保留；本次代理运动的源数据版本同步更新，身体烘焙动画引用直接指向源动画。

此选项只覆盖 Main 的源动画；附加衣物仍独立导出，衣物切换和运行时 CPU/GPU 修正继续使用原流程。点击 **定位结果** 可同时找到源动画、备份和本次新结果。只读源资产、叠加动画或含类型化骨骼属性的源动画会拒绝覆盖；保存失败会尝试恢复源数据及代理版本，并在状态栏报告结果。需要重新调整物理烘焙时，应从 `SourceBackup` 中保留的未烘焙数据恢复源动画后再烘焙，避免把已烘焙的头发运动再次输入物理模拟。

| 按钮 | 行为 |
| --- | --- |
| 编译并预览 | 编译全部参与的图，从预热开始预览 |
| 重置 | 重建预览场景并复位，不自动播放或编译 |
| 烘焙新动画 | 编译全部图，从头模拟并生成动画 |
| 停止／取消 | 停止当前操作，丢弃尚未导出的采样 |
| 定位结果 | 定位当前会话生成的动画资产 |

采样期间保持烘焙面板打开。关闭面板会取消任务；修改源动画或重新编译参与的图也会使当前采样失效，需要重新开始。

## 多部件角色：身体与衣物同步烘焙

每个部件使用独立的 Skeletal Mesh 和烘焙蓝图。先按上面的流程为衣物创建蓝图，例如 `ABP_KawaiiBake_Clothing`，再在主蓝图的 **Parts** 中添加：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| Name | `Clothing` | 非空且唯一；`Main` 是保留名称 |
| Mesh | 衣物 Mesh | 可以与主角色使用不同 Skeleton |
| Graph | `ABP_KawaiiBake_Clothing` | 必须是匹配此 Mesh Skeleton 的烘焙蓝图 |
| Animation | 留空 | 留空时复制源部件姿态；指定时播放此部件自己的动画 |
| Copy Pose From | `Main` | Animation 留空时生效，只能引用 Main 或列表中更早的部件 |
| Relative Transform | Identity | 部件在预览场景中的相对摆放，按实际装配关系设置 |

一次会话的顺序是 `Main → Parts[0] → Parts[1] → …`。复制姿态时读取源部件本步已经完成的最终姿态，按骨骼名称匹配，并换算组件空间；没有匹配的骨骼保留目标 Mesh 的参考局部姿态，再交给该部件的动画图处理。两者至少需要一个同名骨骼，不支持前向引用或循环依赖。

如果为部件填写 **Animation**，它必须与该部件 Mesh 使用同一 Skeleton、为非叠加动画，并与主动画具有相同长度。整个会话的采样率、预热、输出和部件列表由主蓝图控制；作为 Part 使用时，衣物蓝图面板中的 Source Animation 不负责提供输入。

默认会生成 `Main` 和每个 Part 各一条动画，使用相同组 ID、采样率和帧数。开启替换源动画时，`Main` 结果写回源动画，只单独导出各 Part 动画及源动画备份。运行时让各部件播放同一组结果并保持时间同步。

### 身体代理初次烘焙、手动修整与动画回读

这条流程适合抬腿、踢腿等需要人工修整裙摆的动作：`身体代理 → 初次衣物动画 → 手动修整 → 预览并回读衣物轨迹 → 运行时头发代理修正`。

1. 在 Main 的 **主部件代理定义（身体）** 指定绑定身体 Mesh 的代理，配置大腿、膝盖等胶囊。在衣物 Part 开启 **接收身体代理碰撞**。此开关默认关闭；开启后，每步先完成身体姿态，再把同帧身体胶囊转换到衣物组件空间，参与衣物物理计算。预览和初次烘焙使用相同流程，结果写入衣物动画。身体代理的忽略根骨骼列表可以排除指定衣物 Kawaii 节点。
2. 衣物 Part 同时指定自己的 **衣物代理定义**，完成初次烘焙，得到衣物动画及对应 `ProxyMotion`。
3. 点击烘焙面板 **手动修整／回读衣物**，或选中衣物 `ProxyMotion` 后打开 **Tools → Kawaii 衣物动画回读**。也可从代理资产或烘焙动画的右键菜单进入。
4. 点击 **创建修整副本并打开**，在 UE 动画编辑器中修改衣物骨骼关键帧，应用修改并保存。也支持选择原衣物动画进行修整或选择外部编辑后重新导入的动画。保持衣物 Skeleton、原烘焙时长及与身体动作的时间对应关系。
5. 点击 **读取并预览**。窗口同时显示配套身体动画、修整后的衣物和绿色代理。视口下方使用与原烘焙预览相同的帧刻度时间轴、时间／帧数／缓存显示，以及首帧、上一帧、播放／暂停、下一帧、末帧和循环控制；拖动会暂停并即时显示对应帧，关闭循环后停在末帧。可选填运行时相同的 **头发运行时修正配置** 与权重，查看修整衣物对头发的影响。该修正仅用于显示，不改写身体动画。
6. 检查后点击 **更新代理轨迹**。工具先保存 `_BeforeReadback_…` 代理备份，再更新原 `ProxyMotion` 的轨迹及衣物动画引用。原资产路径、身体动作关联和动作集合映射保持不变；运行时缓存会识别新版本。通过 `BakedAnimation` 查找配套衣物动画的播放路径会使用修整动画；直接引用旧衣物动画的播放器需要改为修整副本。

回读直接采样已经应用到 `AnimSequence` 的关键帧，不再执行衣物物理图，因此不会把手动修整覆盖掉。预览显示的衣物姿态就是生成新代理时采样的姿态；代理线框使用运行时轨迹采样器。预览后再次修改动画、骨架或代理定义，需要重新读取；未保存的动画不能发布代理更新。身体源动作改变时须重新烘焙，不能仅靠衣物回读维持动作同步。

身体代理是骨段胶囊碰撞，仍可能留下需要人工修整的布面穿透。回读保留人工结果，但不会自动修复网格权重或未编辑的穿模。与运行时对照时，应使用相同动画、时间、部件变换、代理定义和修正 Profile；游戏中额外的 IK、混合或实时物理会改变输入。

### 可选：衣物对 Main 的碰撞代理

新代理可以独立用于预览，无需维护旧碰撞配置：

1. 在衣物附加部件指定 **衣物代理定义**。
2. 开启 **预览运行时代理修正（仅预览）**，将 **碰撞来源部件** 填为该部件名称，例如 `Base`。
3. **运行时修正配置** 选择角色 `Automatic Clothing Proxy Correction` 节点使用的同一个 Profile，**运行时修正权重** 与节点 Alpha 保持一致。目标骨链、身体胶囊、迭代、接触稳定时间和输出平滑均来自该 Profile。旧版“预览接收骨链”列表不再参与此模式。
4. 修改烘焙面板的预览设置会自动重新预热、重建缓存。编辑代理定义或修正 Profile 后，点击 **编译并预览** 重新生成。状态栏显示代理来源、Profile、骨链数及权重；缺少有效 Profile 时会提示配置，不再悄悄使用另一套物理算法。

**忽略目标骨链是衣物代理本身的规则，同时用于预览和运行时。** 在 `DA_BaseClothing_ClothingProxy` 等定义资产中填写 `Tail_Root`，这套代理就不再对 Profile 中根名为 `Tail_Root` 的目标骨链产生碰撞。两条路径都精确匹配 Profile 的链根名，不自动匹配子树。规则只排除这套代理的接触，保留身体胶囊等其他接触；旧 `ClothingCollisionProfile` 是独立配置。

规则保存在定义资产中，不写死进每个动作的几何快照。修改后**无需重新烘焙代理运动**：运行时下一次采样读取新规则，并通过值类型胶囊传给动画线程。自定义胶囊消费者也需要按 `IgnoredTargetRootBones` 过滤；插件自带 IK 节点已执行该过滤。名单可包含其他角色才有的根名（当前无匹配时不影响其他骨链），最多 64 项且不能包含 `None`。

预览先按烘焙流程完成本帧 Main 与衣物的基础姿态，再用运行时 `SampleSnapshots` / 根骨骼重定位 / `CorrectPose` 执行修正。预览使用 CPU 参考求解，游戏中的 GPU 开关保持可用。修正从正式采样首帧开始积累时间历史，预热仅生成基础物理姿态；显示结果和原生模拟姿态分开保存，拖动已缓存帧不会推进求解或把修正反灌到物理模拟与衣物 Copy Pose。

一致性对照需要相同的基础姿态、代理定义、Profile、Alpha、采样时刻及历史。角色运行时额外的 Control Rig、IK、动画混合或不同帧步长仍可能改变输入；烘焙窗口不会执行角色的完整游戏 AnimBP。该预览不支持从挂接父组件读取 Main 的身体胶囊。

**烘焙新动画** 会重新创建场景，忽略运行时修正的预览结果，代理运动仍正常导出。若需要可换装的通用头发烘焙，保持 **启用旧配置碰撞（写入烘焙）** 关闭；旧开关打开时，其物理碰撞同时参与预览的基础姿态和导出，运行时修正只在预览显示阶段追加，避免预览与导出的基础姿态采用不同配置。

旧配置碰撞的使用方式：

1. 开启 **启用旧配置碰撞（写入烘焙）**。
2. 将 **Collision Source Part** 设为已存在的部件名称，默认 `Clothing`，不能填 `Main`。
3. 指定 `KawaiiPhysicsClothingCollisionProfile`，配置其胶囊及 **Target Root Bones**；根骨骼列表为空时没有消费节点。
4. 将 **Warm Up Frames** 设为至少 `2`。

此处接收碰撞的始终是 Main。动态胶囊来自衣物完成后的骨骼快照，最早下一步供 Main 使用，适合头发与衣物等交互；它不是把所有 Mesh 自动变成三角网格碰撞体。普通共享碰撞同样需要在 KawaiiPhysics 节点配置发布、接收和分组，并让依赖源排在消费部件前面。

## 烘焙结果与限制

- 独立输出记录各 Mesh 的真实骨骼最终局部变换和浮点曲线，不复制 Anim Notify、同步标记或 typed attributes。开启替换源动画时，源资产自身的 Notify 和同步标记会保留；含 typed attributes 的源资产暂不支持覆盖。
- 保留局部根骨骼运动。预览 Actor 固定在原地，不模拟角色移动逻辑或提取组件位移；输出继承相应源动画的 `Enable Root Motion`，并关闭 `Force Root Lock`。
- 时长按采样帧率向上对齐，末帧读取源动画的准确终点，因此结果可能比源动画长不到一帧。
- 源动画时长必须大于 `0` 且不超过 `600` 秒。全部部件的总骨骼数 × 采样关键帧数不能超过 `4,000,000`。
- 模拟在独立预览世界中进行，禁用 Mesh 的 Post Process Anim Blueprint。需要烘焙的处理应放入烘焙图。
- 不支持 World Collision、场景 Wind、自定义 Blueprint 外力或启用的 Wind 外力。其他启用的外力要求 `Random Force Scale Range` 两端相等且有限，以保证重复采样。
- 骨骼和部件变换必须有效，缩放必须为正且非零。
- 只有完成全部采样和前置校验后才创建结果。若导出构建或回读校验失败，新资产可能保留为未保存状态；若磁盘保存失败，可能只有部分结果已写盘，请依据面板错误检查并手动保存。

播放已烘焙的物理骨链时，通常应关闭同一骨链上的实时 KawaiiPhysics，避免再次叠加物理模拟。

## 物理校准：生成可复用的实时配置

### 操作流程

1. 打开 **Tools → Kawaii 物理校准**，或点击衣物 AnimBP 工具栏的 **物理校准**。从工具栏打开时会自动填入该蓝图及其 Preview Mesh。
2. 设置 **人物骨骼网格体、衣物骨骼网格体、衣物相对变换、衣物动画蓝图**。用 **物理根骨骼** 唯一选中一个 KawaiiPhysics 节点；`None` 只适用于图中仅有一个节点的情况。节点在 Linked AnimBP 中时，选择实际包含节点的蓝图。
3. 点击 **读取碰撞与骨链**，检查并调整碰撞形状及骨链活动范围。导入优先读取所选节点及其 Limits Data Asset 的胶囊和外侧球体；没有可用形状时再读取人物 Physics Asset。此按钮会重建编辑列表，覆盖面板中已有的手动调整。
4. 将人物动画序列拖入下方测试动作区域，可多选追加。动画必须与人物 Skeleton 一致且非叠加。列表按顺序播放；关闭 **播放前重置** 可测试动作衔接，过渡时长默认 `0.2` 秒。也可设置压力测试骨骼及局部偏移，模拟身体 IK 带来的姿态变化。
5. 至少保留一个参与搜索的动作。建议另外添加独立片段，同时勾选 **仅用于验证** 和 **播放前重置**；这些片段用于检查候选在独立动作上的表现，不计入训练动作评分。关闭 **播放前重置** 的片段会延续前序物理状态，不能视为独立验证。
6. 默认开启 **搜索节点参数**。按需要开启 **搜索 Physics Settings**、**搜索 Bone Constraints**，设置绝对参数范围和骨骼配对候选方案，再点击 **开始节点参数搜索**。全部候选由原生 Kawaii CPU 模拟评估；**CPU 搜索候选数**默认 `64`，增加数量会延长搜索时间。关闭 **搜索节点参数** 时，按钮改为 **开始旧 GPU 搜索**，恢复 GPU 倍率筛选后 CPU 复验的流程。
7. 检查完成状态与报告。通过验收的改进结果可点击 **保存配置**；找到改进候选但未达到验收阈值时，按钮显示 **保存最佳候选（未达标）**，可保存后试用，但不代表通过验收。节点参数搜索中，原配置候选 `0` 仍为最佳时，工具报告未找到优化结果，不输出替代配置；旧 GPU 模式保留其倍率基准输出行为。
8. 保存后点击 **应用到蓝图**。节点参数搜索的结果会保存获选参数方案；此按钮一并写回所选节点的 Physics Settings、Bone Constraints 相关参数，绑定校准配置并编译蓝图，可撤销。未达标候选应用后仍保留未达标状态，需检查实际动作中的穿透和拉伸。检查效果后自行保存蓝图。如果源节点在校准后发生变化，需要重新校准。**直接把配置资产拖入节点的 Calibration Profile 槽，不会自动写回保存的节点参数方案。**

校准读取所选 Kawaii 节点，在独立原生动画图中回放，不执行完整衣物 AnimGraph。节点参数搜索的基准保留已有校准配置；新候选使用自己的接触配置和节点参数，避免叠加倍率。旧 GPU 模式仍使用原有倍率基准。生成配置后，游戏内由 CPU 执行 KawaiiPhysics。

搜索在指定范围、候选数量和骨骼配对方案内采样，按评分及验收条件选择结果。它只代表**本次有限候选中的最佳结果，不保证全局最优**；结果受测试动作、评分权重和验收阈值影响。搜索期间不会修改源蓝图，保存配置也不会写回节点；写回发生在点击 **应用到蓝图** 时。

### 节点参数搜索范围

- **Physics Settings**：搜索阻尼 `Damping`、刚度 `Stiffness`、骨骼碰撞半径 `Radius` 和摆动角度 `LimitAngle` 的绝对值范围。它们不是相对于原参数的倍率。角度范围仍受节点角度曲线影响，开启 **尝试恒定角度曲线** 可将常量曲线也作为候选；检查已有曲线及面板的骨链范围覆盖。
- **Bone Constraints**：搜索碰撞前／后约束迭代次数、约束柔顺度候选、纵向／横向细分以及横向碰撞反馈范围；**尝试关闭半径自动加密**允许测试关闭该选项的候选。
- **骨骼配对候选方案**：每项填写方案名称、是否替换原有约束和骨骼配对列表；关闭替换时追加到原有配对。工具只测试提供的方案，不会自动猜测裙摆或衣摆应连接哪些骨骼。配对两端需位于当前可动骨链内，不允许自连、重复或使用固定根端点。列表留空仍可搜索现有约束的求解参数。
- 搜索保留所选根骨骼，不搜索 `WorldDampingLocation` 或 `WorldDampingRotation`。关闭某一类搜索可保留该类原设置，只搜索另一类。

### 常用参数

| 参数 | 默认值 | 范围 / 说明 |
| --- | --- | --- |
| 搜索节点参数 | 开启 | 开启时全部候选使用原生 CPU 模拟；关闭时使用旧 GPU 倍率搜索 |
| CPU 搜索候选数 | `64` | 节点参数搜索使用，范围 `2–256`；候选越多，模拟耗时越长 |
| 阻尼 / 刚度绝对范围 | `0.1–0.6` / `0.02–0.3` | 节点参数搜索使用 |
| 骨骼碰撞半径 / 摆动角度范围 | `0.5–3 cm` / `35–110°` | 节点参数搜索使用；角度 `0` 表示不限制角度 |
| 采样帧率 | `60` | `30–120` |
| 预热帧数 | `30` | `0–240`，预热不参与评分 |
| GPU 候选数量 | `128` | 仅旧 GPU 模式；`8–1024`，包含基准配置 |
| CPU 复验候选数量 | `4` | 仅旧 GPU 模式；`1–16`，基准配置额外验证 |
| 随机种子 | `1337` | 相同输入和种子产生相同候选组合 |
| 阻尼 / 刚度倍率范围 | `0.5–2` | 仅旧 GPU 模式；相对于原节点参数，合法范围 `0.1–4` |
| 骨骼碰撞半径倍率范围 | `0.75–1.5` | 仅旧 GPU 模式；合法范围 `0.25–4` |

| 最大允许穿透 / 骨长误差 | 各 `0.5 cm` | 决定是否通过验收；超标改进候选只能按未达标结果保存供试用 |
| 输出目录 | `/Game/KawaiiCalibration` | 必须是有效的 `/Game/` 子目录 |

### 保存、手动调整及限制

- **保存测试集** 创建 `DA_CalibrationTestSet_<id>`。在内容浏览器选中测试集，再点击 **载入所选测试集** 载入工作副本；再次保存会创建新资产。
- **保存配置**或**保存最佳候选（未达标）**创建 `DA_KawaiiCalibration_<id>`。完成评估后，诊断报告写入项目 `Saved/KawaiiCalibration/<guid>/report.json`。未达标但优于基准的获选候选仍可单独保存和应用供试用，报告和配置保留未达标说明；保存或应用不会将它标为验收通过。基准候选获胜时仅报告未找到优化结果，不生成新配置。
- 打开保存的配置资产，在 **优化节点参数** 中可展开查看获选的 Physics Settings、Bone Constraints、曲线及细分等具体数值；这些数值由校准面板的 **应用到蓝图**写回所选节点。
- 不进行搜索时，可调整碰撞与骨链后点击 **保存手动配置（未验收） → 应用到蓝图**。此方式不需要测试动作，保留原节点阻尼、刚度和骨骼半径，不生成蒙皮接触点，也不代表通过穿模验收。再次调整后需重新保存手动配置。
- 节点参数搜索使用原生 CPU 模拟，不依赖 GPU 候选筛选。仅旧 GPU 倍率搜索需要实际图形接口和 **SM5 计算着色器**，不支持 `NullRHI`，不会自动退回 CPU 筛选。
- 待校准节点应使用 **Component Space** 和显式重力，关闭世界碰撞、风力、外力数组、共享碰撞发布/接收、同步骨骼、旧版重力和项目默认重力，简单外力设为零。可用蓝图副本准备符合这些条件的节点。
- 身体碰撞需要 `1–32` 个启用的球体或胶囊，不支持插槽。形状编辑模式下全部禁用不会恢复自动导入。
- 若提示找不到受模拟根影响的可读取蒙皮顶点，检查所选根骨骼及衣物蒙皮；也可将蒙皮顶点采样数设为 `0`，但此时验收仅覆盖骨骼代理。
- 删除或禁用碰撞形状时，保留 **替换原碰撞的骨骼** 列表可避免原碰撞重新生效；清空该列表表示叠加原碰撞。修改骨链范围时须勾选相应覆盖开关；摆动角度 `0` 表示不限制角度。
- 节点参数搜索默认从衣物输入姿态中的同名身体骨骼读取碰撞，适用于独立烘焙部件；缺少绑定骨骼时会报错。衣物骨架不包含完整身体骨骼时，可启用 **从挂接人物读取身体碰撞**。此时人物应先完成动画和 IK，再更新衣物，且应是衣物的骨骼父组件；碰撞来源父组件不能使用 Leader Pose。旧 GPU 模式保留从挂接人物读取的行为。

碰撞代理及采样验收不能保证三角网格完全无穿模；仍需在实际角色和未参与搜索的动作中检查效果。

## 运行时：烘焙衣物的 IK 修正

当身体经过足部 IK 等处理后，烘焙衣物可能与身体错位。可在普通运行时 AnimBP 中使用 **Baked Clothing IK Correction** 节点（分类 `Kawaii Physics | Runtime Correction`）。

### 创建 Profile 并接入动画图

1. 创建普通 **Data Asset**，类型选择 `KawaiiPhysicsIKCorrectionProfile`。
2. 在 **Chains** 中配置 `Root Bone`、`Tip Bone` 和 `Driver Bone`。例如衣物链从裙摆根到末端，Driver Bone 选对应大腿。Root 必须有父骨骼，Tip 必须是其后代；各链根子树不能重叠，Driver 必须位于所有修正子树之外。
3. 在 **Capsules** 中配置身体胶囊的起止骨骼、骨骼局部偏移和半径。`End Bone` 留空时使用 Start Bone，半径必须大于 `0`。
4. 添加节点并指定 Profile，按下面的关系接入。这两路都是局部空间 Pose，不需要为此节点添加 Local/Component 转换。

```text
烘焙动画姿态 ───────────────→ Baked Pose
                              Baked Clothing IK Correction → Output Pose
身体最终 IK 后的姿态 ───────→ Driver Pose
```

两路输入必须对应同一动画时刻，且都属于当前 Mesh 的 Skeleton。节点保留 Driver Pose 的身体姿态，将指定衣物子树的烘焙局部动作放到当前身体锚点下，再进行链条与胶囊修正；侧枝和 Tip 之后的后代保留烘焙局部动作。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| Driver Weight | `0.65` | `0–1`，附加身体驱动影响由根部的 0 增长到末端设定值 |
| 链 Collision Radius | `1 cm` | 骨链碰撞半径，允许为 0 |
| 胶囊 Radius | `5 cm` | 必须大于 0 |
| Iterations | `16` | `1–64` |
| Alpha | `1` | `0–1`，减小会削弱碰撞修正；0 仍保留当前锚点下的烘焙衣物，并非直接透传 Driver Pose |
| Use Attached Parent For Collision | `false` | 默认从 Driver Pose 读取胶囊骨骼；启用后读取最近挂接的父级 Skeletal Mesh |

分体衣物启用父级碰撞时，确保身体先完成更新，例如为衣物组件设置 `AddTickPrerequisiteComponent(Body)`；父组件不能使用 Leader Pose。此开关只改变胶囊来源，两路 Pose 仍必须属于衣物 Mesh 的 Skeleton，需要在衣物图中准备匹配的驱动姿态。

最多支持 `64` 条链和 `64` 个胶囊，当前 LOD 必须保留所需骨骼。缺少 Profile、缺骨或链配置无效时，节点回退到完整 Driver Pose；可在动画调试信息中查看原因、剩余穿透和骨长误差。这是骨骼链与胶囊的近似修正，不是完整布料模拟。

## 衣物代理：自定义运动资产与烘焙头发修正

此功能全部位于 KawaiiPhysicsBaker 插件。衣物代理运动使用独立的 Data Asset 保存**代理端点所需的最小骨骼层级、局部变换轨道和局部形状定义**，运行时不解码衣物 AnimSequence，也不读取衣物组件的上一帧姿态。衣物显示仍可使用同次烘焙输出的动画。

### 创建与编辑衣物代理

1. 打开 **Tools → Kawaii 衣物代理**。也可以先在内容浏览器选择衣物 Mesh 或已有代理定义，再打开面板。
2. 选择衣物网格体，点击 **创建代理定义**，保存 `Kawaii 衣物代理` 资产（默认目录 `/Game/KawaiiProxies`）。已有资产可直接从 **代理定义** 选择器载入。
3. 选择起点骨骼并点击 **添加代理**。默认连接该骨骼与第一个子骨骼；没有子骨骼时为球体。右侧属性可以修改唯一名称、两端骨骼、局部偏移和半径；两端重合即为球体。最大支持 64 个代理，绑定真实骨骼，不支持虚拟骨骼或插槽。
4. 左侧显示参考姿态和代理线框。点击线框或从视口上方列表选择代理，选中项以黄色高亮；使用 UE 变换手柄编辑，**W** 移动、**R** 缩放、**F** 聚焦选中代理。移动可选 **整体／起点／终点**，也可点击端点选中；端点偏移会分别换算到各自绑定骨骼的局部空间。缩放时局部 **X/Y 调整半径、Z 调整胶囊长度、中心手柄等比缩放**；球体各轴均调整半径。一次拖动对应一次撤销，支持 **Ctrl+Z / Ctrl+Y**，松开后右侧属性同步刷新。动作中的代理效果请在烘焙面板开启 **显示衣物代理** 检查。
5. 如果衣物有 PhysicsAsset，可以点击 **追加 PhysicsAsset 代理** 导入其球体和胶囊；不修改原 PhysicsAsset，不导入盒体或凸包，导入后仍需检查贴合情况。
6. 点击 **校验并保存**。修改直接作用于所选定义资产，并支持撤销／重做；修改网格、形状或骨骼绑定后，需要重烘对应运动资产。

### 同步导出代理运动与动作集合

在烘焙面板的 Main 或对应衣物 Part 上指定 **衣物代理定义**，定义的网格必须与该部件相同。**代理动作集合** 可选择该衣物之前生成的集合；第一次可以留空。未选代理定义时保持原有动画烘焙行为。

除原有 AnimSequence 外，每个选定部件还会输出：

| 资产 | 内容 |
| --- | --- |
| `…_ProxyMotion` / `Kawaii 衣物代理运动` | 代理形状快照、最小父子层级、逐帧局部变换、源动作身份、对应衣物动画、采样信息及生成组 |
| `…_ProxySet` / `Kawaii 衣物代理动作集合` | 同一衣物的源动画到代理运动资产映射；已有集合按源动画替换条目，旧动画及旧运动资产不会被覆盖 |

集合保存的是运行时可读取的引用，不依赖编辑器包元数据。首次生成集合并成功保存后，工具会将它回填到对应部件的烘焙设置，记得保存烘焙蓝图。此后烘焙新动作会追加映射，重烘同一动作会替换映射。集合不能混用不同衣物网格、代理定义或装配变换。所有生成结果通过校验后才更新集合；磁盘保存失败会明确报告，可能留下部分已保存结果和待保存的集合。

时间轴与衣物输出动画一致：采样点为 `i / SampleRate`，最后一个采样点保存源动作准确终点，输出时长向上对齐到整帧。正式轨道不包含预热。动画轨道和代理轨道合计沿用 400 万骨骼样本上限。

### 运行时选择、采样与头发修正

蓝图接口在 **Kawaii Physics → Baked Clothing Proxy** 分类中：

1. 身体实际播放器提供本帧的 `FKawaiiClothingProxyActionSample` 数组：`SourceAnimation`、该源序列内的秒数 `Time`、非负 `Weight`。Montage 必须先换算当前动画片段内时间；该接口不会根据身体最终 Pose 自动推断源动作，也不会自动订阅 Montage 或状态机。
2. 调用 **Resolve Clothing Proxy Actions**，传入当前衣物的 `Kawaii 衣物代理动作集合`，得到本帧对应的代理运动采样数组。缺少映射或源动作重复时返回失败并清空结果。输出条目的 `Motion.BakedAnimation` 是对应衣物显示动画的软引用，应在进入动作前加载；不要每帧同步加载。
3. 调用 **Sample Blended Clothing Proxy Motion**；单动作也可调用 **Sample Clothing Proxy Motion**。`ProxyToTarget` 是衣物 Mesh 组件空间到头发所在 Mesh 组件空间的变换，必须由调用方提供。资产的 `RelativeTransform` 仅记录烘焙时摆放，不会再隐式叠加；按原装配关系且目标为 Main 时，可直接使用该记录值。
4. 将输出值数组传入 **Baked Clothing IK Correction → Clothing Proxy Capsules**。为头发骨链创建 `KawaiiPhysicsIKCorrectionProfile`：Chains 填头发 Root/Tip，Driver 选择修正子树以外的头部骨骼；只需要碰撞修正时可将 Driver Weight 设为 0。`Baked Pose` 输入同一时刻的烘焙头发姿态，`Driver Pose` 输入身体当前姿态，两者仍须属于头发所在 Mesh 的 Skeleton。

采样函数在游戏线程调用，动画工作线程只接收已经变换到目标组件空间的胶囊值数组。每帧更新数组；采样失败时传入空数组并处理返回的 Error，避免继续使用上一次动作的碰撞。Alpha 建议为 1，低于 1 会削弱最终接触修正。原有 Profile 身体胶囊与外部衣物代理可以同时参与求解。

采样器会先在局部骨骼空间进行插值／混合，再重建父子层级及碰撞形状。正权重动作必须使用相同定义、骨骼层级、衣物网格和装配变换；全零权重没有可采样姿态，返回失败。时间超出片段时钳制到首末帧，不自行循环或推进播放时钟。代理形状变化后，旧运动资产会被拒绝。

### 自动跟随当前动作与动态换装

在普通角色 AnimBP 的 AnimGraph 中添加 **Automatic Clothing Proxy Correction**（`Kawaii Physics | Runtime Correction`），连接：

```text
当前动作分支 → Automatic Clothing Proxy Correction → Output Pose
```

节点读取该输入分支本帧已经同步完成的播放器记录，按动画身份、序列内时间和权重匹配衣物代理；不需要逐个 Sequence Player 设置代理。输入姿态作为骨链修正基准，身体姿态保留，Profile 指定的头发／衣物链参与碰撞修正。它不自动播放或替换可见衣物动画，衣物仍需与身体按同一动作、时间和混合规则播放对应烘焙结果。

**从早期自动节点版本更新：**重新打开并编译使用该节点的 AnimBP，然后保存。旧输入引脚会自动迁移并保留连线，无需删除节点或重新烘焙。这修复了输入属性与输出引脚同名、导致编译后的姿态连接在运行时被清空的问题。

1. **Profile** 选择头发／衣物链的 `KawaiiPhysicsIKCorrectionProfile`。这是每种角色骨架配置一次的 Root／Tip／Driver 列表；本节点以同一输入作为基准和驱动姿态，Driver Weight 不额外产生身体 IK 差值，碰撞修正仍有效。需要两路姿态之间的 IK 重定向时继续使用原 `Baked Clothing IK Correction`。
2. **Proxy Motion Set** 选择当前衣服已有的 `_ProxySet`，或通过 **Proxy Motions** 传入该衣服全部 `_ProxyMotion`；两种输入只能选一种。每个列表只放同一套衣物定义的动作。一次最多 256 个动作，快照合计最多 400 万骨骼关键帧。
3. 将集合或数组引脚连接 AnimBP 的实例变量。换装完成资源加载后，替换该变量；清空表示关闭衣物代理。无需改每个动画节点，也不要修改多个角色共享的集合资产来表达某个角色的换装。
4. 默认 **Use Baked Relative Transform** 使用烘焙时衣物相对 Main 的摆放。如果当前目标不是原 Main 或装配改变，关闭它，提供当前衣物到目标 Mesh 组件空间的 **Proxy To Target**。
5. 使用 Montage 时，将 **Montage Slot** 一次性设置为该分支中唯一的全身 Slot 名。节点换算 Montage 当前片段的序列时间，并跟随混合权重；不需要逐 Montage 配置。编译 AnimBP 时会自动安装本帧 Montage 采样子系统，更新插件后需重新编译使用该节点的 AnimBP，无需更换 AnimInstance 父类。
6. **代理跟随当前根骨骼**（`Follow Live Root`，默认开启）：代理轨道按烘焙预览的方式录制，不提取 Root Motion，代理根骨骼带着整段动作的位移。运行时提取 Root Motion（例如攀爬、落地 Montage）后，开启此项会将代理从录制根骨骼刚性移到当前根骨骼，避免录制轨迹使碰撞体偏离身体。录制根骨骼转换到 Main 组件空间后，直接与同空间的当前根骨骼对齐；当前根骨骼不能再乘一次衣物相对变换。Motion Warping 的角色世界位移和旋转由组件统一携带，不再叠加到代理上。动画调试中的 `root reanchor` 显示本帧对齐距离。
7. **代理跟随当前身体姿态**（`Follow Live Body Pose`，默认开启，需同时开启根骨跟随）：每个代理端点跟随其最近的同名身体骨骼，保留衣物部件相对该骨骼的烘焙运动。攀爬时，Motion Warping 改变角色与世界坐标手部目标的关系，身体 IK 还可能移动骨盆、胸部和手臂；只对齐根骨会使代理停留在 IK 前的位置。此项在代理采样时应用当前身体姿态，预览和 CPU/GPU 修正共用同一份对齐结果。Profile 中受修正的骨链及其子树不作为跟随锚点，避免反馈；缺少同名骨骼时沿父链查找，最终退回根骨对齐。关闭此项可对比原来的仅根骨对齐行为，现有代理资产无需重新烘焙。

**时间稳定**由 Profile 的 **接触稳定时间**（`SettleTime`，默认 0.08 s）和 **输出平滑时间**（`SmoothingTime`，默认 0.03 s）控制。每帧从上一帧的修正结果（相对骨链锚点保存，身体移动不会拖尾）出发，按接触稳定时间回到输入姿态再解算接触，并保持接触在胶囊原来的一侧。历史有效时，自由骨骼点会检查两次采样之间的扫掠，结合胶囊上一帧的位置与轴向，处理骨链或代理快速跨越的情况；沿历史接触方向推出时计算该方向的实际出口距离。输出平滑和骨长恢复后会再次投影碰撞约束，避免把已推出的骨链重新带回代理内部。CPU、GPU 和烘焙窗口预览使用相同规则，无需为特定动画或骨骼另设补丁。

扫掠采用相对运动的线性近似，不能保证任意大角度运动、整个骨段扫掠面或网格表面都无穿透；固定根部、相互冲突的约束及代理覆盖不足仍需检查。两项时间都设为 0 时恢复无历史的逐帧独立解算。超过 0.25 s 的时间断档、LOD 变化、衣物快照被替换、修正被跳过的帧都会让下一帧从无状态解算重新开始。直接调用 `CorrectPose` 的代码需先调用 `AccumulateDeltaTime` 上报帧时间，否则按无状态解算。

支持非叠加 Sequence Player、Sequence Evaluator、普通全身权重混合，以及不含逐骨插值的 BlendSpace。该节点须放在共享 **Save Cached Pose 之前**，以便标记自己的输入分支。缓存被多个分支消费、Linked Anim Graph 跨实例、Layered Blend Per Bone、Mesh Space 混合、Additive、镜像、Inertialization 等不属于可精确重现的输入；不要把这些图当作普通全身混合。某些不支持的路径可以检测并拒绝，单靠播放器记录无法识别全部姿态修改。输入身体 IK 可以先完成，但衣物代理仍表示烘焙衣物的姿态；额外衣物 IK／实时物理不会自动反映到轨道。

列表更新后，旧代理立即停用，最迟下一次游戏线程 PreUpdate 建立新快照后恢复（通常一个动画更新）。轨道仅在列表或关联改变时复制，动画线程只读取纯值快照；忽略目标骨链每帧更新，无需重烘。资产列表应提前加载，节点不在求值中同步加载资源。混合到没有代理映射的动作（例如待机）时，已映射动作继续采样，修正强度为节点 Alpha × 已映射动作总权重，随动作混合自然退出；全部动作均无映射时保留输入姿态。无效资产或播放器贡献不完整仍会停止本帧修正；动画调试中可看到原因、动作数、胶囊数和最终修正强度。

烘焙播放结束后，实时 Kawaii 从 Alpha 0 恢复时，以当前动画姿态重新建立模拟状态，丢弃暂停前的速度、组件位移和子步缓存，交接首帧不预热或推进物理。由 Set Alpha 通知从非零低权重恢复时保留正在显示的模拟位置，只清理残留速度。通知的 Blend Out Time 仍决定权重恢复时间；它和 Montage 自身的混合时间分别控制实时模拟恢复与烘焙动作退出。

**已有身体烘焙动画的升级：**新烘焙的代理自动保存 `BodyBakedAnimation`，可直接识别同次烘焙的 Main 动画。对于旧资产，在内容浏览器选中 `_ProxySet`，执行 **Tools → 升级所选衣物代理动作集合**。工具按原有生成组、源动作、Main 标记补全关联，无需重新模拟；搜索代理运动所在目录及子目录。若 Main 已移到其他目录，恢复同目录关系后再升级。遇到缺失或重复候选会报告错误，不猜测文件名。原始源动画及代理记录的衣物烘焙动画也可直接识别。

**原生碰撞与横向虚拟接触。** 从 KawaiiPhysics 节点生成 Profile 时，会导入节点及 Limits Data Asset 的外侧球体、胶囊、盒体和半径曲线；未配置的盒体不会凭空生成。纵向骨段已经使用连续线段碰撞。横向覆盖沿用 [KawaiiPhysics 的虚拟骨骼细分思路](https://pafuhana1213.github.io/KawaiiPhysics-Portal/en/docs/features/bone-subdivision)：导入开启横向细分的 `Bone Constraints` 骨骼对，也可在 Profile 的 **横向虚拟接触** 中显式指定相邻链端点。每条连接支持 1–10 个碰撞采样点；端点球已覆盖的参考跨度跳过细分。采样点只检测碰撞，不增加真实骨骼或重复执行重力、风力、距离弹簧。

CPU 预览和 GPU 运行时都会先汇总所有接触点对同一端点的位移，再按 `max(1, 总权重)` 归一化反馈。未碰撞的点不稀释推力，连接顺序也不改变本轮反馈。**横向接触迭代**控制反馈与原骨链约束交替求解的次数。节点中没有横向骨骼对时，导入结果为空；它不会自动连接空间上相近但实际独立的发束。节点设置是在生成 Profile 时导入，修改节点后应刷新 Profile；手工配置的连接应另存配置，避免刷新时被源节点配置替换。

横向细分只能补足所选骨链之间的覆盖，不能保证覆盖骨链外侧的全部发片；不合适的连接也可能把原来分开的卷曲发梢拉向同一侧。增加采样点不等于消除所有网格穿模，需同时检查全段动画、正常待机和实际蒙皮。固定根部与混合蒙皮权重仍保持原有行为。

**骨链角度与弯曲约束。** 每条链的 **修正偏转角上限**（`LimitAngle`）与 **偏转角曲线** 限制单个骨段相对当前输入姿态的额外偏转，生成配置时从 KawaiiPhysics 节点导入，并按原始骨链深度映射到拆分后的链。Profile 的 **启用修正偏转角限制** 可单独关闭它，保留导入数值供对比。这里的参照是修正器接收到的、已经完成驱动映射的动画姿态；它不是原生物理求解前的姿态，因此相同数值不代表两个阶段有完全相同的绝对角度范围。

**相邻骨段弯曲变化上限**（`MaxBendChange`）限制相邻两段相对于输入动画的折角变化，用三点约束共同调整关节及两侧可移动端点，不会统一把原本卷曲的发梢拉直。它没有原生节点的直接对应参数，需要在 Profile 中设置；重新生成配置时保留相同 Root/Tip 的此项调节。两个角度值都以度为单位，`0` 表示关闭，旧资产默认保持原行为。根部位置、蒙皮权重和共享父骨骼的参与范围不因此改变。

CPU/GPU 在每轮骨长投影后执行相同的角度和弯曲投影，再进行碰撞；平滑后的复投影与横向接触迭代也使用这些约束。碰撞优先，所以遇到互相冲突的限制时仍可能有角度残余，不能保证两个上限都被严格满足。输入发片本身已穿透时，过小的偏转上限可能阻碍避让；可分别比较“仅偏转”“仅弯曲”和二者同时开启，而不是默认把所有限制设得很紧。

**网格包络测量仅作诊断，实验性整链包络默认关闭。** `MeshEnvelopeRadius` 是发片到骨链的最大参考距离，不是整条发束在所有方向上的厚度。把它统一当作碰撞半径会撑开原本正常的发型，因此生成或刷新测量数据不会自动启用该效果。常规预览与运行时继续使用原有配置半径。旧 Profile 可关闭“实验：使用整链网格包络（可能撑开发型）”以恢复原有发型。

胶囊代理是近似体积，可能包含真实衣物表面以外的空隙；即使使用蒙皮表面采样，强行消除所有“代理内穿透”也可能破坏正常造型。后续精度验证需区分代理重叠与真实网格相交，同时检查正常姿态是否变形，不能只以代理内穿透降为零或求解路径一致作为验收标准。

项目诊断 `KawaiiPhysicsBaker.ContactAudit.ProjectLanding.History` 连续检查 `Land_3h` 全部帧，比较保留历史、关闭两项时间、中途清空历史、增加迭代和不应用修正的输入姿态。只修改临时 Profile，不保存资产。结果写入 `Saved/KawaiiContactAudit`：`landing-*.csv` 记录代理重叠及固定根段，`pose-*.csv` 记录骨骼与代理位置，`surface-*.csv` 记录 LOD 0 蒙皮后的头发／衣物三角面交叉。三角面检测不包含材质透明遮罩和 Morph，不直接等同于最终像素穿模；诊断运行通过也不代表已经消除穿模。`IdleGeometry` 提供正常待机的同类对照。

### 一致性与当前边界

- 支持非叠加动作使用统一骨骼权重的局部姿态混合。任意分层遮罩、Mesh Space 混合、Inertialization、Control Rig 和额外衣物 IK 不会被自动重现；衣物显示与代理必须使用一致的姿态计算规则。
- 记录的局部根运动原样保留。自动节点开启“代理跟随当前根骨骼”时会把代理对齐到当前根骨骼；手动采样接口（`Sample Clothing Proxy Motion` 等）不做此处理，若身体提取了 Root Motion，调用方须自行保证代理使用同样的根处理，不能只靠组件变换抵消不一致的骨骼轨道。
- 不包含 Chaos 布料、Morph、材质顶点位移和网格精确接触。球体／胶囊是近似形状；高领等无法通过有限骨链位移避让的接触仍可能有残余穿透。
- **Validate Proxy Motion** 做完整轨道校验，并在源资源已加载时检查参考骨架签名及编辑器源动画版本。适合装配／加载时或编辑器验收时调用，不应每帧执行。常规采样只检查结构、定义及实际访问的轨道，且不会加载软引用。
- 自动节点可代为发布支持的动作分支采样；手动接口仍适用于项目自行管理动作的场景。两种方式都需要接入角色 AnimBP，并确保衣物显示同步；工具不会自动改写现有角色蓝图。

## GPU 视觉修正（试验）

运行时 IK Correction 和 Automatic Clothing Proxy Correction 可以把骨链碰撞求解与最终蒙皮放到 GPU。默认在 **Game / PIE** 中允许启用，只有实际成功执行了修正才会挂载 GPU Mesh Deformer；Automatic Clothing Proxy 需要先匹配到已烘焙的代理动作。普通待机、没有代理映射或修正停止时使用原来的动画与蒙皮路径。控制台可随时切换：

```text
a.KawaiiPhysicsBaker.GPU 1
```

切回原 CPU 求解：

```text
a.KawaiiPhysicsBaker.GPU 0
```

切换在组件下一次动画更新时生效，并重置求解历史。不需要改动 Profile 或烘焙资产；动画图需要满足下述节点顺序。普通编辑器预览、离线烘焙和 NullRHI 继续使用 CPU，避免把未修正的 CPU 姿态写进烘焙结果。

GPU 路径保留每条骨链内部的约束顺序、接触侧历史、锚点空间稳定和输出平滑。独立骨链按线程组提交，输出修正矩阵，再按原骨骼权重执行 GPU 蒙皮；支持 Morph Target、位置与切线输出，前帧顶点由 Mesh Deformer 接口管理。运行时不回读 GPU 结果、不等待 GPU fence。**CPU 骨骼查询、Socket、后续 CPU 动画节点和碰撞查询看到的是基础姿态，不能把视觉修正用于游戏逻辑。**

CPU/GPU 对固定根部嵌入胶囊的情况采用相同规则：允许第一骨段从该胶囊内部伸出，继续处理自由骨骼点和后续骨段的碰撞。根部不能移动，因此不会反复尝试把整条起始骨段推出；不可消除的根部穿插仍会计入诊断残余值。

**GPU 修正节点应接在 Control Rig、IK 等骨骼修改节点之后，紧接最终输出。** 后续混合或 Post Process AnimBP 也不能再改变修正链的组件空间姿态，否则修正矩阵与最终蒙皮姿态不一致，会造成拉伸。提交前会核对修正链与最终组件姿态；发现差异时丢弃该修正包、记录骨骼名称并自动退回 CPU。该节点保持 CPU，避免逐帧反复挂载；调整动画图后，先执行 `a.KawaiiPhysicsBaker.GPU 0` 并让动画更新，再执行 `a.KawaiiPhysicsBaker.GPU 1` 重试，或重启 PIE。

常规 GPU 工作通过场景的 `EndOfFrameUpdate` 提交，在 SkeletalMesh 渲染命令管线更新骨骼后执行，避免身体蒙皮读取旧帧。立即更新路径也遵守该命令管线的先后关系，不要求关闭并行渲染命令管线。同一次动画求值再次更新渲染数据时可以复用求解结果，但仍重新执行蒙皮。

首次进入有效修正时先用 CPU 求解过渡帧，再在游戏线程挂载 GPU Deformer；停止修正后卸载，恢复原来的蒙皮。挂载或卸载尚未生效的过渡帧仍输出当前姿态的基础蒙皮，但不执行碰撞求解，避免显示 T Pose 或上一个动作的修正结果。

当前版本需要 SM5 及以上实际图形接口；已有其他 Mesh Deformer、Chaos Cloth、Leader Pose、单链超过 64 点、同一 Mesh 同帧存在多个修正节点等情况保留 CPU 路径。GPU 只对允许 Mesh Deformer 的 LOD 生效。渲染输入不可用时回到 CPU，日志会提示；可用 `GPU 0` 再 `GPU 1` 重试。

确认启用时，日志会出现 `GPU correction active`，包括链数、点数、顶点数和 LOD。`a.KawaiiPhysicsBaker.GPU.Status` 可在日志中查看资源就绪状态、提交次数及最近一次跳过原因；没有代理动作映射时，CPU/GPU 两条路径都不会执行修正。使用 `stat gpu` 查看 **Kawaii Physics Correction**，或在 GPU profiler 中查看 `KawaiiGPU Solve` / `KawaiiGPU Skin`。CPU 图中的 `Correction: solve chain` 下降仅表示计算已迁移；比较性能时还要看 GPU、渲染线程和最终帧时间。

Development 下可用 `a.KawaiiPhysicsBaker.GPU.ValidateFrame 1` 对照提交时的组件姿态与渲染端实际骨骼矩阵，日志中的 `mismatched` 应为 `0`。此诊断逐帧复制矩阵并写日志，有额外 CPU 开销，默认关闭；检查后设回 `0`，不要带着它做性能对比。

这是骨链层面的视觉碰撞，仍需在实际动作中检查穿插、阴影、描边、运动矢量及网格包围盒。GPU 自动化对照需真实 RHI，测试名称为 `KawaiiPhysicsBaker.GPU`；测试专用回读不进入运行时路径。

## 性能探针与耗时采集

运行时代理、头发／衣物骨链修正及烘焙导出已加入静态 CPU Trace 计时区间。使用 Unreal Insights 的 **Timing Insights**，筛选 `KawaiiBaker_`，在选定时间段查看调用次数、平均／最大耗时、Inclusive 和 Exclusive 时间。游戏线程的代理采样与动画工作线程的修正分别记录，不应只看 GameThread。

| 计时区间 | 测量范围 |
| --- | --- |
| `KawaiiBaker_Proxy_ResolveActions` | 身体源动作到当前衣物代理运动的映射查找 |
| `KawaiiBaker_Proxy_SampleBlended` | 整次代理采样与混合；子项拆分为 `ValidateHeader`、`SampleLocalPose`、`BlendLocalPoses`、`BuildHierarchy`、`BuildCapsules` |
| `KawaiiBaker_Proxy_SampleSnapshots` / `ReanchorCapsules` | 自动节点在动画线程上的快照采样，以及把代理对齐到当前根骨骼 |
| `KawaiiBaker_Proxy_ValidateAsset` | 完整资产校验，单独区分装配／验收成本与每帧采样成本 |
| `KawaiiBaker_Proxy_DefinitionSignature` / `SkeletonSignature` | 定义及参考骨架签名计算 |
| `KawaiiBaker_Correction_PreUpdate` | 游戏线程上的配置和父级碰撞快照 |
| `KawaiiBaker_Correction_Update` / `Evaluate` | 动画节点更新／求值；包括上游 Pose 的开销，分别以 `InputDriverPose`、`InputBakedPose` 子区间标出 |
| `KawaiiBaker_Correction_SolveChain` | 单条骨链的约束求解；`MeasureResiduals` 单独记录残余穿透及骨长诊断 |
| `KawaiiBaker_Correction_ResolveChains` / `PrepareCapsules` / `SolveAndReconstruct` / `WriteOutputPose` | 骨链解析、碰撞准备、求解及变换重建、最终姿态写回 |
| `KawaiiBaker_Bake_*` | 准备、各部件求值、轨道采集、代理数据构建、动画生成与回读校验、映射更新、各资产保存 |
| `KawaiiBaker_PreviewProxy_EvaluateParts` | 启用运行时代理预览时的整次部件求值，包含基础物理模拟、同帧代理采样和修正；不是纯碰撞增量成本 |

总区间包含子区间，**不要将父子 Inclusive 时间相加**。多工作线程耗时相加是 CPU 工作量，不等于整帧墙钟时间；以时间轴判断并行及阻塞。烘焙会在开始、完成、失败和取消时生成 `KawaiiBaker` 书签，便于定位一次操作；不输出逐帧日志。

在编辑器或 Development 游戏的控制台中可以直接开启统计面板：

```text
stat KawaiiPhysicsBaker
```

面板显示动作映射、代理采样、完整校验、快照、节点求值、骨链求解的 CPU 周期统计，以及每帧求解调用数、骨链点数和实际迭代数。计数累计所有实例；节点求值仍包含输入 Pose 开销，求解是其子项。

完整采集示例（开始前确保没有正在写入的其他 Trace，并使用新的输出文件名）：

```text
Trace.File D:/UEProject/RPGProject/Saved/Profiling/KawaiiBaker/Attack.utrace cpu,counters,frame,bookmark
Trace.Bookmark KawaiiAttackBegin
```

执行攻击／落地或烘焙操作，结束后输入：

```text
Trace.Bookmark KawaiiAttackEnd
Trace.Stop
```

也可启动时传入 `-trace=cpu,counters,frame,bookmark -tracefile=<绝对路径>.utrace`。采集后用同版本 Unreal Insights 打开文件。Counters 面板的 `KawaiiBaker/Proxy/InputSamples`、`ActiveSamples`、`Bones`、`Capsules` 表示**最后一次游戏线程采样调用**的负载，不是所有角色之和；`KawaiiBaker/Correction/*LastSnapshot` 是最后一个节点的配置快照。同帧多角色会更新这些共享 gauges，应结合对应 CPU 事件位置读取。

需要进一步拆分求解器内部时，开启：

```text
a.KawaiiPhysicsBaker.ProfileSolverDetails 1
```

这会记录每次迭代的 `LengthConstraints`、`PointContacts`、`SegmentContacts`、`FinalPointContacts`，默认值为 `0`。详细探针本身有开销，定位后设回 `0` 再测整体预算。未启用对应 Trace 通道时不会写入事件；Shipping 是否保留探针取决于引擎的 Trace／Stats 编译选项。以上探针测 CPU 耗时，不代表 GPU 渲染或布料求解耗时。

## 基础碰撞体与横向接触试验

运行时自动代理修正的 CPU 和 GPU 路径支持球体、胶囊和定向盒体。代理定义中勾选“使用盒体”，以“起点骨骼 / 起点局部偏移”指定中心，设置盒体旋转与**半尺寸**；终点和胶囊半径不参与盒体求解。非均匀缩放按最大轴缩放保守扩大盒体。衣物代理面板支持盒体线框、移动、分轴缩放及 PhysicsAsset 盒体导入，旋转在属性面板编辑。几何变化后须重新烘焙相应代理动作；旧胶囊定义的签名保持兼容。

修正配置中的“碰撞半径曲线”为基础半径的倍率，按骨链长度归一化，空曲线等于 1。生成配置时会读取原 KawaiiPhysics 节点的曲线，在真实骨骼处按原模拟根骨骼的长度比例采样，避免分支重新从曲线起点开始，也避免用全曲线最大半径撑开整条头发。原节点与 LimitsDataAsset 中的外侧球体、胶囊、盒体可以导入；Plane、内侧球体和 PhysicsAssetForLimits 不在此生成器的导入范围内。

“横向虚拟接触”在**明确指定的两条不同骨链**之间补充碰撞采样点，把接触位移反馈给两端，再恢复各自骨链的长度与碰撞约束。它默认空白，可从原节点已启用的 BoneConstraintSubdivision 对应连接导入，也可手工指定 BoneA/B；每条连接 1–8 个采样点、Feedback 0–2（0 关闭该连接），最多 128 条，迭代 1–16 次。不会自动把左右头发全部连接，也不会重新叠加已烘焙的重力、风力或 XPBD 距离弹簧。纵向骨间隙继续使用已有的连续线段接触检测。

GPU 将横向反馈与骨链投影分成有序计算阶段，连接反馈按固定顺序串行执行以避免端点写冲突，各条骨链投影和蒙皮并行；运行时不读回 GPU，也不切回 CPU。连接数和横向迭代数会增加 GPU 调度与求解成本，应只添加需要的相邻连接。

盒体支持自动代理修正预览、代理动作采样和 Main 身体代理对衣物的烘焙碰撞。旧版衣物碰撞快照桥接只支持球/胶囊，遇到盒体会明确报错；请使用自动代理修正预览。

这仍是骨骼与基础碰撞体的近似修正，骨链无穿透不代表所有蒙皮三角面无穿透。Land_3h 的完整 81 帧试验中，直接把两个现有胶囊换成包围盒没有解决持续穿模；31 条后发横向连接降低了部分表面交叉，但第 5–48 帧仍有残余。试验使用临时配置，原资产未被自动覆盖。整链网格包络仍默认关闭。

## 常见问题

| 现象 / 提示 | 处理方式 |
| --- | --- |
| 看不到 物理烘焙 按钮 | 通过 Tools 菜单创建专用烘焙蓝图；普通 AnimBP 不会显示此按钮 |
| `Select a Main Mesh and Source Animation` | 在面板补齐 Main Mesh 和 Source Animation |
| `uncontrolled animation player` / `exactly one connected Bake Source Pose` | 删除普通播放器，确保只有一个 Bake Source Pose 且实际参与输出求值 |
| `Bake Source Pose was not evaluated` | 检查断线、混合权重或绕开源节点的分支 |
| Skeleton 或动画长度不匹配 | 直接播放要求 Skeleton 相同；独立部件动画还必须与主动画等长；不同 Skeleton 的部件可使用 Copy Pose From |
| `translation retargeting would discard that motion` | 报错骨骼的平移已被图修改，但 Skeleton 模式会丢弃它；在目标烘焙 Skeleton 中将相关骨骼的 Translation Retargeting 设为 Animation，或取消该平移变化后重新烘焙。工具不会自动修改 Skeleton |
| `shared collision registry is unavailable` | 启用插件后完整重启编辑器 |
| Output Directory 无效 | 使用 `/Game/KawaiiBakes` 一类已注册的内容路径；不能填 `D:\...` 或 Engine 内容目录 |
| 动画开始时物理未稳定 | 增加 Warm Up Frames，并重新预览；它会在动作起始姿态上预热 |
| 预览耗时与动画时长不同 | 预览按采样率控制播放节奏，但每个编辑器帧最多推进一个固定模拟步，以保持共享碰撞时序；编辑器帧率低于采样率时会放慢。首次跳到未缓存位置还需要预热和顺序补算 |
